# PC 1.8.7 — STM32 и Tab5 в одной программе

Имя приложения — `krenomer.exe`. STM32 подключается по USB с автопоиском
`0483:5740`; Tab5 — по вручную выбранному USB COM или TCP через «Wi-Fi»
(AP `192.168.4.1:5000` либо STA-IP прибора, порт 5000, ключ прибора).

## Что изменилось после 1.8.2

- Присутствует исправление экспорта 1.8.3: сетка отчёта вмещает дополнительные
  столбцы двух постов и плеч от борта, исключения сохранения показываются в UI,
  новый комплект не перезаписывает предыдущий. [Описание](EXPORT_FIX_1.8.3.md).
- Сохранены свежесть `S`/`R`, разрывы графика при устаревших данных и диагностика
  последовательности `R` из 1.8.6. Старт/стоп записи ПК и Tab5 синхронизируются
  при поддержке `rec_sync_cap`/`rec_sync` прошивкой; для старой STM32 эта функция
  не предполагается. [Контракт](record-sync-proposal.md).
- Исправлен учёт пустого второго поста. Для каждого включённого переноса с
  конечным `h` считается число конечных `dThetaPost`; число пригодных постов —
  минимум этих значений, при отсутствии таких переносов — 0
  (`src/core/HeelRs.hpp`, `RsFinish`). Второй CSV без данных выбранной оси
  больше не даёт положительную отметку комплектности сам по себе.

## Как открыть прежний опыт и сохранить отчёт

1. Сохраните копию прежнего `*.krenomer` вместе с исходными записями.
2. В 1.8.7 откройте «Обработка → Открыть проект → Открыть файл проекта…»
   или нажмите **Ctrl+O** и выберите старый `*.krenomer`. При открытии папки
   с проектом используйте «Открыть проект из этой папки».
3. Если записи перемещены и не найдены, нажмите «Указать файлы…» и выберите
   соответствующие исходные файлы. Проверьте ось, привязку постов, реверс,
   границы положений, параметры опыта и включённые в расчёт переносы.
4. При необходимости сохраните проект через «Сохранить проект как…»
   (**Ctrl+Shift+S**), чтобы оставить прежний вариант для сравнения.
5. Выберите «Сохранить отчёт → Краткий» (**Ctrl+R**) или «Полный»
   (**Ctrl+Shift+R**). Полный вариант добавляет расчёт по шагам.
   В меню можно выбрать родительскую папку и имя комплекта.
6. Каждый экспорт получает новую папку, например `Отчёт_M025`, затем
   `Отчёт_M025 (2)`. Книга `Отчет_Кренование.xlsx` и подготовленные PNG лежат
   вместе. Предыдущий комплект и исходные записи не перезаписываются;
   при ошибке частичный новый комплект сохраняется для проверки.

## Сборки и границы проверки

- **x64** — для 64-битной Windows; **x86** — для 32-битной Windows.
  Обе сборки называются `krenomer.exe`; выбирайте каталог своей архитектуры.
  В текущей рабочей копии это `pc/build-tab5-x64` и `pc/build-tab5-x86`.
- Имеющиеся журналы `Testing/Temporary/LastTest.log` обеих сборок фиксируют
  успешные стендовые проверки без физических приборов: имитатор, loopback,
  разбор данных и экспорт. Это не проверка USB/TCP на настоящем Tab5 или STM32.
  Окончательный прогон: **18/18 CTest на каждой архитектуре**, в том числе
  новая регрессия пустого поста; UI — 452 проверки на каждой. На копиях двух
  записей M025 отдельно сохранены краткий и полный отчёты с графиками
  (35 проверок на каждой архитектуре). [Подробности](VALIDATION_1.8.7.md).
- Проверка таблиц импорта **CheckWin7Imports** для x64/x86 выполнена.
  Целевая ОС — Windows 7 SP1 и новее; запуск на физической Windows 7,
  работа её USB-драйверов, OTA и восстановление на приборе не проверялись.

Прошивки **остаются отдельными**: STM32 F411 `.bin` для DFU; Tab5 ESP32-P4
приложение для OTA и отдельный комплект для ROM recovery. Общее имя программы
не объединяет образы прошивок. Полный relative-режим Tab5 и дальнейшее управление
identity/capabilities описаны в [UNIVERSAL_APP_1.8.7.md](UNIVERSAL_APP_1.8.7.md).
