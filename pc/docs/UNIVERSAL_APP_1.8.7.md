# Единая программа STM32 + Tab5: вывод для 1.8.7

Срез анализа: `fix/pc-universal-744913`, исходный HEAD `c3ab941` (PC 1.8.6);
сравнение с `467c6ec` (PC 1.8.4). Ссылки `файл:строки` ниже относятся к этому
срезу, пути — от корня репозитория. Это анализ кода; сборка, проверка экспорта
и выпуска выполняются отдельно. Проверок физических приборов здесь не было.

**Сергей, одну программу для ПК можно использовать уже сейчас для основного
сценария кренования обоих приборов.** В 1.8.6 это уже общий исходник, хотя имя
выходного файла — `krenomer-esp32`. Полное совпадение функций пока отсутствует.
Рекомендуемый результат — один PC exe и две отдельные прошивки, с явным
определением прибора и доступных команд. Переписывать приложение целиком не нужно.
Основание: `pc/CMakeLists.txt:54–95`, `pc/src/ui/App.cpp:138–169`.

## Что уже общее и где различия

| Область | Фактическое состояние и доказательство |
| --- | --- |
| Связь | Один `DeviceLink` поверх `IConnection`: очередь команд, ответы, `status`, поток `S`, отсчёты `R`. В каждый момент выбран один транспорт, одновременных двух приборов нет (`pc/src/comm/DeviceLink.hpp:7–14,134–167`; `pc/src/ui/App.cpp:138–169`). |
| STM32 USB | Автопоиск только `0483:5740`, затем `ver`; вручную можно выбрать другой COM. VID/PID — кандидат, окончательное принятие сейчас по ответу `BWM427` (`pc/src/comm/SerialConnection.hpp:135–154,271–285`; `pc/src/comm/DeviceLink.cpp:362–372`). |
| Tab5 USB / TCP | USB использует тот же SerialConnection, COM выбирается вручную. TCP — отдельный транспорт: IPv4, порт, токен, `auth`, затем общий `ver`. Интерфейс предлагает AP `192.168.4.1:5000` либо фактический адрес STA (`pc/src/ui/App.cpp:430–476`; `pc/src/comm/TcpConnection.hpp:15–34,58–65,117–118`). Прошивка направляет USB и авторизованный TCP в общие обработчики (`tab5/main/main.c:632–642`; `tab5/main/tab5_services.c:814–817`). |
| Запись на ПК | `samples on` → `R` → `TakeSamples` → Recorder → CSV по датчику и необязательный XLSX. Это общий путь, отдельно от прореженного `S` для экрана (`pc/src/ui/AppRecord.cpp:144–174,258–292`; `pc/src/core/PcRecorder.hpp:2–20`). STM32 и Tab5 реально формируют одинаковый `R` с одинаковыми масштабами (`BWM427_Inclinometer/Core/Src/usb_cli_ext.c:724–744`; `tab5/main/main.c:740–746`). |
| Файлы и обработка | Общие `files/get`, приём G/D/E с CRC, загрузка CSV, расчёт и экспорт. Обычный CSV Tab5 совпадает с форматом записи ПК (`pc/src/ui/AppFiles.cpp:20–24,200–211`; `pc/src/core/Download.hpp:1–4`; `pc/src/core/CsvLog.hpp:2–16`; `tab5/main/tab5_services.h:15`). |
| Управление записью прибора | Tab5 имеет `rec on/off`, `rec_sync_cap` и `rec_sync`; PC включает синхронизацию по capability. Текущая STM32-прошивка пишет по физическому переключателю и не реализует эти команды/флаг синхронизации (`tab5/main/main.c:485–486,596–612`; `pc/src/ui/App.hpp:275`; `BWM427_Inclinometer/Core/Src/usb_cli_ext.c:485–490,876–894`; `BWM427_Inclinometer/Core/Src/usb_cli.c:896–914`). |

## Падение отчётов 1.8.2

Известный фикс PC 1.8.3 присутствует в обеих линиях: `fd703a2` входит в историю
`467c6ec`, а в Tab5 изменение внесено коммитом `6660d0e` (сам `fd703a2` не является
предком `c3ab941`). Ошибка возникала при непрерывной записи, двух постах и плечах от борта:
строка из 11 столбцов попадала в сетку из 10. Сейчас ширина определяется заранее,
`Grid::Row` расширяет сетку, `Put` проверяет границы
(`pc/src/core/HeelProtocol.hpp:95–101,154–178,648–651`).

Экспорт резервирует новую папку, разруливает одинаковые имена и ловит исключения
фонового сохранения (`pc/src/core/ExportTarget.hpp:124–169`;
`pc/src/ui/AppProcess.cpp:812–838,889–910`). Эти три файла на срезе `c3ab941`
совпадают с `fd703a2`; причина и регрессии описаны в `pc/docs/EXPORT_FIX_1.8.3.md:3–23,53–62`.
Следовательно, объединение платформ само по себе не требует нового экспортёра.
Наличие исправления в исходниках не доказывает, какой exe запускался при жалобе,
и не закрывает все возможные причины падения: нужен отдельный прогон исходных
данных Сергея и точного выпуска. Здесь он не выполнялся.

## Прошивки: маршруты должны оставаться раздельными

- **STM32:** свой F411 `.bin`, проверка векторов, размера и строки проекта;
  `boot` → DFU `0483:DF11` → запись → чтение и сравнение. Распознанный Tab5
  блокируется и страницей, и `Updater::Start`
  (`pc/src/fw/Firmware.hpp:73–121,431–435,464–466,538–584`;
  `pc/src/ui/AppFirmware.cpp:40–48`).
- **Tab5 OTA по USB/TCP:** требуется точное `board=tab5 chip=esp32p4 proto=2`;
  проверяется приложение ESP32-P4 с проектом `krenomer-esp32`, версия и образ.
  Ответ OTA повторно проверяет identity; успех требует новой версии и подтверждения
  загрузки. STM32 не проходит этот вход (`pc/src/core/Protocol.hpp:464–485`;
  `pc/src/fw/EspOta.hpp:78–104,171–184,286–310`).
- **Tab5 ROM recovery:** отдельный manifest из четырёх частей, ручной COM,
  закрытие рабочего транспорта, проверка P4 chip ID 18, ревизии и защиты до
  записи. STM32 не проходит проверку кристалла
  (`pc/src/fw/RomRecovery.hpp:28–47,308–342`; `pc/src/fw/EspRom.hpp:207–220`).
  ROM подтверждает кристалл, но не модель платы Tab5: её выбирает пользователь
  (`pc/src/ui/AppFirmware.cpp:399–413,435–436`).

Для распознанных приборов пересечение штатных маршрутов запрещено кодом.
Абсолютную защиту для любого неизвестного устройства заявлять нельзя:
STM32-ветка использует запрет Tab5 вместо положительного STM32 identity,
а DFU выбирается по общему VID/PID без привязки к серийному номеру
(`pc/src/fw/Firmware.hpp:431–432,456–465,538–539`).

## Реальные оставшиеся пробелы

1. **Identity и capabilities ещё не единый контракт.** Подключение принимает
   любой ответ с префиксом `BWM427`; неизвестный `proto` превращается в 1,
   `samples` предварительно определяется по версии ≥1.5. Нужны явный профиль
   STM32/Tab5/неизвестный и перечень разрешённых команд; для старой STM32 —
   ограниченный legacy-профиль. Номер версии и TCP не должны заменять identity
   (`pc/src/core/Protocol.hpp:476–499`; `pc/src/comm/DeviceLink.cpp:367–372,488–495`).
2. **Возможности нужно привязать к текущему подключению.** При переоткрытии
   status не очищается, а общий `HaveStatus()` проверяет только Connected и
   haveStatus. Для часов уже есть проверка `statusAt >= connectedAt`; её принцип
   нужен и остальным управляющим действиям. Автопродолжение записи после разрыва
   также не сравнивает постоянный ID прибора — это риск смешения сессий, не
   воспроизведённый здесь дефект (`pc/src/comm/DeviceLink.cpp:281–322`;
   `pc/src/ui/App.hpp:275,294–296`; `pc/src/ui/AppSettings.cpp:133–153`;
   `pc/src/ui/AppRecord.cpp:272–289`).
3. **Настройки требуют capability-gating.** PC предлагает `gap=2…100`,
   `batalarm` и смену Modbus-адреса; Tab5 допускает gap только `15…100`, а
   `batalarm`/`addr` в её обработчике отсутствуют. Эти элементы нужно ограничить
   возможностями прибора (`pc/src/core/Protocol.hpp:678–685`;
   `pc/src/ui/AppSettings.cpp:96–102,158–162,536–544`;
   `tab5/main/main.c:549–629`).
4. **Блокировки записи и обновления не везде общие.** `StartPcRecording`
   проверяет только STM32 updater, без OTA/recovery; этот вход следует учитывать
   в общей блокировке операций (`pc/src/ui/AppRecord.cpp:128–148`). Это вывод
   по коду, без воспроизведения гонки.
5. **Полный функционал Tab5 — дальнейшая работа.** Прибор уже публикует
   `dual_mode_cap`/`instrument` и пишет отдельный `_REL.CSV` с качеством пар;
   типизированный PC status и CSV-обработка пока не представляют этот режим и
   аудит качества (`tab5/main/main.c:487–488,583–591`;
   `tab5/main/tab5_services.c:269–285,378–384`;
   `pc/src/core/Protocol.hpp:274–330`; `pc/src/core/CsvLog.hpp:412–420,490–504`).
   Доступ к файлам также выбирает SD с приоритетом над USB, без явного выбора
   носителя в PC (`tab5/main/tab5_services.c:558–584`;
   `pc/src/ui/AppFiles.cpp:20–24,200–211`).

**Решение сейчас:** единый PC для кренования, обычных записей и отчётов;
отдельные STM32 DFU, Tab5 OTA и Tab5 ROM, доступные по подтверждённому профилю.
**Дальше:** закрыть перечисленные ограничения возможностей и добавить Tab5
relative/носители отдельными расширениями. Совместимость на физических STM32,
Tab5 USB/TCP и Windows 7 из этого анализа не следует; её проверяют отдельно.
