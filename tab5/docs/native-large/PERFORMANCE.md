# Производительность native large UI 1.7.0 — host-only

Три последовательных quiet-раунда: 17 сцен × 2 темы × 400 шагов × 3 = **40 800 измерений**; перед каждой сценой 40 warmup-шагов. Все проверки PASS. Production/firmware и версия не менялись.

Исходная база Git `5f9b33b94790a40fd110a0a60b7b54a07759e2f6`; точные SHA рабочего production и harness — в [run.json](performance/run.json). Это SHA-снимок рабочего дерева, а не утверждение, что все измеренные файлы уже входят в Git commit. Freeze: [freeze.json](performance/freeze.json).

## Условия и границы

- Windows QPC, GCC 14.2.0, `-std=c11 -O2`, assertions включены; `NUI_PROFILE_PRIMITIVE_TIMING=0`, release `NUI_PROFILE_FINE_COUNTERS=0`.
- Генерация fixture/синусов, статистика, CSV/JSON I/O и проверки эквивалентности находятся вне timed-участка. Внутри: UI update, tick/очередь, render и синхронное расширение RGB565→RGB888 в mock sink. Copy вынесен в отдельную метрику; render ниже исключает copy.
- Числовые входы и точное целочисленное расширение RGB565 взяты из `native_baseline_contract.h` v1. Для качки добавлены меняющиеся roll, для записи — duration/bytes; геометрия и интеракции — новый v2 workload.
- Логический шаг — 100 мс; статичный focus проверяется шагами 10 мс (4,4 с с warmup, до таймаута 15 с). Это virtual cadence, не частота кадров, достигнутая устройством.
- Перед каждым раундом два quiet-сэмпла; во время замеров compiler/build-процессы проверялись каждые 250 мс. Обнаружений нет. Это не гарантия отсутствия любой нагрузки ОС; max включает preemption.
- Это host CPU. ESP32-P4, PSRAM, PPA, поворот и LCD/DSI/DMA не измерены. Текущий native port при наличии dirty всё равно поворачивает/передаёт полный framebuffer; уменьшение CPU dirty не означает пропорционального сокращения аппаратной передачи.

## Update, render и наблюдения

Полные p50/p95/max/mean для update, input/queue, render без copy, copy и render с copy, а также distributions только реально отрисованных кадров (`active_frames`) находятся в JSON; сырые шаги — в 34 CSV из `performance/samples/`.

| `angles_force_full` | 0.0122/0.0210 | 0.8623/1.0777 | 1.5466/1.8090 |

- **Статичный idle: 0 отрисованных кадров, 0 dirty pixels, 0 flush calls** в обеих темах для `idle_poll`, `idle_update`, `focus_idle`, `queue_idle_event`, `queue_empty_touch`. Скрытые live updates на настройках/сети также не создают рендеров.
- График ограничен production throttle 200 мс, поэтому рендерится 600 из 1200 шагов/тему. Общий p50 включает пропуски; только активные кадры тёмной темы: 0.7065/0.9461/1.3976 мс (p50/p95/max).
- `time_sync_caret_idle` — не статичный idle: textarea мигает каждые 400 мс; за 400 шагов 100 blink-кадров и один кадр скрытия encoder focus после 15 с. Это ожидаемая анимация, не обязательная регрессия.
- Клавиатурный шаг — реальный queued touch down/release, попеременно backspace/6; изменение года переключает валидность календаря. Заметный dirty объём соответствует клавиатуре и modal, а не полной сцене.
- Для каждой из 34 комбинаций в каждом раунде итоговый partial framebuffer побайтно равен forced-full redraw (102 проверки). Каждый измеренный шаг проверяет equality dirty pixels и mock-copy pixels. После destroy/deinit нет живых renderer allocations; callbacks backend не вызываются.
- `angles_force_full` — контроль того же текущего UI/входов с принудительной полной invalidation, допустимый для оценки dirty-пути. Это не сравнение с LVGL. Явной обязательной регрессии не найдено, оптимизации production не вносились.
- Fine0 primitive counters отключены: нули `primitive_calls` не означают отсутствие примитивов. Числа update/render/flush calls учтены независимо. Новых instrumented profiles не запускалось.

## Что допустимо сравнивать с прежним LVGL

Старый matched-layout benchmark v1 сравнивал LVGL `369c7fc`, native `c49eacf` и optimized `0dee13b5`: одинаковый UI, adapter/pump 5×40 мс, warmup 120, 600 шагов, 3 сбалансированных раунда, 54 000 raw steps. Исторические p50/p95 и SHA исходной таблицы сохранены в [historical-compatible.json](performance/historical-compatible.json); этот старый замер заново не запускался.

**Делить новый 1.7.0 large UI на старый LVGL нельзя:** изменились шесть страниц, шрифты/размеры, modal/time keyboard, количество pump/render calls, время виртуального шага и dirty workload. Из данного отчёта не следует, что новый UI быстрее/медленнее старого LVGL.

## Воспроизведение

Из корня workspace, при остановленных тяжёлых сборках:

```powershell
python tab5/tests/run_native_large_bench.py --frames 400 --warmup 40 --repeats 3
```

Runner сохраняет SHA-снимок до компиляции, выполняет GCC последовательно, затем quiet timing. При compiler-процессе или изменении source SHA результат отклоняется. Абсолютные build paths/логи остаются только в `.tools/native-large/performance/`; переносимые JSON/CSV этого отчёта используют relative/`WORKSPACE` paths.
