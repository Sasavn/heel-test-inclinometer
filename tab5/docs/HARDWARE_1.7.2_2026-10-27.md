# Tab5 1.7.2: уведомления, время и запуск с носителями

После аппаратного исправления памяти в 1.7.1 оператор подтвердил появление
времени и показателя CPU на физическом экране. По его новым замечаниям:

- Шрифт служебного уведомления увеличен с 20 до 36 px; панель вмещает две
  строки. Шесть host-изображений в обеих темах проверены на размещение текста,
  границы и работу закрытия. Это изображения renderer, не фотографии платы.
- После подключения STA один раз за запуск выполняется асинхронный NTP-запрос.
  Начало откладывается при записи измерений или другом запросе времени.
  Автоматического бесконечного повтора нет; кнопка «По WiFi» сохранена.
  Worker не меняет часы: основной поток применяет результат к системным
  часам и RTC с сохранённым часовым поясом. Ошибки выводятся пользователю.
- USB status дополнен состоянием и сообщением синхронизации.

## Аппаратное подтверждение

P4 revision103/ST7121, COM11 на HASEE, 27.10.2026. SHA256 приложения:
`e04d7e417689c1f8cf07400c9bd498b9f398d2870dcc86742dcf152556dca9b4`.
Четыре части подтверждены ROM-MD5, NVS сохранена, boot_confirmed=true.

После первого запуска время автоматически синхронизировалось по WiFi без
команды установки с ПК. Повторный аппаратный reset со вставленными SD и USB
также прошёл: на uptime4с обе файловые системы FAT32 готовы, SD error0;
на uptime14с STA подключена и виден автоматический запрос NTP. RTC сохранила
время между перезапусками. USB-команды и UI не блокировались, счётчики
sample/USB/storage/routing drops оставались нулевыми.

Оператор сообщил о погасшем экране при подключении USB, затем подтвердил,
что всё заработало; событие совпало по времени с нашим перезапуском после
прошивки. Самостоятельный дефект питания этим не установлен. Полное
обесточивание не эквивалентно выполненному аппаратному reset и пока не
подтверждено.

255 в панели отсутствующего датчика — насыщаемая серия неудачных опросов
RS485, не пропуски отрисовки. При 300 таймаутах series=255, total errors=300;
правильный ответ сбрасывает серию. В отдельном аппаратном UI perf были
draw_errors=0. Датчики оператор ещё не подключал.

Числа общего/свободного места на носителях в этой версии ещё не передаются
из backend в UI; это отдельное замечание оператора, а не доказательство
неисправности FAT32. Запись измерений, полное обесточивание и rev3 этим
прогоном не проверялись. Публичный релиз не создавался.
