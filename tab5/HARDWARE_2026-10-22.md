# Tab5: первый аппаратный запуск, 22.10.2026

По прямому запросу пользователя плата прошита через USB на компьютере группы
`!Уник` в `mesh-replica`. Порт перед записью проверен по Espressif VID303A/PID1001;
ROM прочитал chip18, silicon103 (P4v1.3), security flags0. Использован образ100–199.

## Результат первого запуска 1.6.2

Последующее ускорение и актуальная прошивка описаны в
[отчёте 1.6.3](PERFORMANCE_2026-10-22.md).

- Проверенная тогда версия **1.6.2-esp32**, `ota info`: `boot_confirmed=true`.
- Последняя проверка: uptime264с, USB `ver`/`status` отвечают, RTC установлен
  на22.10.2026 16:13:29 (Москва), AP поднят на192.168.4.1.
- BSP определил **ST7121**, touch FW1 (1.80.1.16),720×1280. Реальные reset/init/on/
  touch прошли; основной цикл после создания UI работает. Внешний вид и попадания
  пальцем на физическом экране отдельно не подтверждались.
- Все4 factory-части проверены MD5 самим ROM; записано1699152байта. NVS не
  стиралась; прежние freq10Гц, alpha0.15 и остальные настройки сохранились.
- Временные задания прошивки удалены после завершения. GUI компьютера не
  занимался; внешних сообщений и публикации исходников не было.

## Что обнаружил именно аппаратный запуск

1. Версия1.6.1 падала на `sdio_mempool_create` из-за нехватки внутренней DMA RAM.
   Включён официальный `CONFIG_ESP_HOSTED_MEMPOOL_PREFER_SPIRAM` для P4/32MiB PSRAM.
2. Штатный `bsp_display_start()` просил большие внутренние DMA draw buffers.
   Main теперь вызывает `bsp_display_start_with_config`: два PSRAM-буфера по
   720×32pixels, software rotation сохранён. Дизайн Roboto/f085c29 не изменён.
3. RESET GPIO15 оставался LOW после последовательности ESP-Hosted; C6 не
   отвечал на SDIO. Явно выбран `CONFIG_ESP_HOSTED_SDIO_RESET_ACTIVE_HIGH`, который
   в этой реализации заканчивает импульс уровнем HIGH. После этого C6 отвечает
   и AP работает. См. [описание ошибки в репозитории M5Stack](https://github.com/m5stack/M5Tab5-UserDemo/issues/1)
   и [рабочую конфигурацию ESPHome](https://github.com/esphome/devices.esphome.io/blob/main/src/docs/devices/M5Stack-Tab5/config.yaml).
4. BSP повторно захватывал LDO4 при каждой неудачной попытке mount без SD,
   затем возвращал `already in use`. Аппаратный SD backend теперь владеет одним
   power handle на срок работы и одним card handle; форматирование отключено,
   прежняя FAT32-проверка сохранена. Отсутствие карты не блокирует основной цикл.
5. При первой ROM-записи Windows COM вернул пустой read через50мс, раньше
   command deadline. В автономном инструменте для этой операции добавлено
   ожидание полного deadline. Production PC exe не изменён; его WinRomTransport
   требует отдельной коррекции этого поведения. После исправления инструмента
   весь ROM transfer и MD5 прошли на железе.

## Остаточные ограничения

Д2 и Д3 имеют `ABSENT`: успешные реальные измерения не получены. Карта не
определяется (`sd_err=263`, timeout); работа с носителем и запись не подтверждены.
USB-A накопитель не смонтирован. C6 сообщает старую/необъявленную версию0.0.0
против host2.13.0: базовый AP работает, но совместимость всех RPC, TCP и нагрузки
не проверена. C6 в этой операции не перепрошивался. Изменена только P4 firmware.
Power-cut/rollback, длительная работа и взаимодействие с физическими датчиками
остаются отдельными испытаниями.

## Сборки и регрессии

Обновлены оба реальных IDF-профиля100–199/300–399 с версией1.6.2. Аппаратно
прошит и проверен только103. Повторные28 actual-image OTA/ROM/recovery mock
прогонов прошли на x64/x86; service234850 + startup86 assertions PASS.
Математика, CSV/wire handlers, STM32, PC production и дизайн UI не менялись.
Изменены аппаратные allocation/mount/config и номер версии.

Размеры, SHA и краткое аппаратное свидетельство: [HIL JSON](docs/HIL_1.6.2_2026-10-22.json).
Полные журналы хранятся локально в ignored `.tools/hardware*-boot.log` и на
целевом компьютере в `C:\Tools\fw\tab5-1.6.2-20261022`; raw RAM dumps не публикуются.
