# Проверки локального порта Tab5

Дата: 21 октября 2026. База STM32/ПК: `9226894`, ветка `tab5-esp32`.
Проверки проводятся без физических COM/USB, без окна приложения и без прошивки
устройства. Публикация на GitHub не выполняется.

## Что перенесено

ESP-IDF 5.5.2, BSP Tab5 1.3.2, LVGL 9.3.0, esp_lvgl_port 2.6.2.
Датчики 2/3 по Modbus, медиана/EMA и отдельная качка X/Y, сенсорные экраны
1280×720, часы RX8130 и напряжение INA226. Ошибка одного носителя изолируется
от другого; очереди записи не зависят от сетевых команд и перерисовки.
AP/STA через ESP-Hosted C6, авторизованный TCP 5000 и проводной USB Serial/JTAG,
OTA в неактивный раздел с SHA256 и подтверждением успешной загрузки.

ПК: TCP, распознавание платформы, отдельные страницы Tab5 OTA и первоначальной
установки/восстановления через ROM, файлы `krenomer-esp32.exe` x64/x86.
Прежний STM32 DFU сохранён. Сборки не открывают реальные COM-порты.

## Команды проверки

Из корня отдельной рабочей копии:

```text
tab5\tests\run-host.cmd
python tab5\tools\gen_fonts.py --check
python tab5\tests\run_ui_test.py
python tab5\tests\test_services_run.py
tab5\build.cmd
tab5\build.cmd rev3
ctest --test-dir pc/build-tab5-x64 --output-on-failure
ctest --test-dir pc/build-tab5-x86 --output-on-failure
pc\tests\run-service-integration.cmd
```

Дополнительно для каждого настоящего комплекта (`PACKAGE` — build/package или
build-rev3/package):

```text
pc\build-tab5-x64\esp32_test.exe --image PACKAGE/krenomer-esp32.bin
pc\build-tab5-x64\recovery_test.exe --manifest PACKAGE/krenomer-esp32.json
pc\build-tab5-x64\esprom_test.exe --package PACKAGE 100
pc\build-tab5-x64\esprom_test.exe --package PACKAGE 300
```

## Область виртуальных проверок

- Измерения: разбор кадра, CRC/адрес/функция/длина, знаки и диапазоны,
  ошибки/возврат датчика, фильтры, обнуление, временное окно и гистерезис качки.
- Экран: настоящий LVGL без окна, десять состояний, геометрия без пересечений;
  полное покрытие строк шрифтами (195/195/18 глифов).
- Хранение: настоящий C-код сервиса с подменой границ файловой системы,
  планировщика и flash; точные CSV и округление, независимые очереди,
  переполнение, потеря/переподключение носителя, ENOSPC, ошибки записи/fsync,
  запрет подключения носителя посреди записи. Длинная выгрузка проверяется
  по байтам и CRC; большое число assert здесь не означает столько сценариев.
- Запуск: общий производственный порядок инициализации с инъекцией отказов
  USB/MSC, netif, Wi-Fi и TCP listener. После отказа USB действительно создаётся
  CSV на SD, а вызывающий код продолжает запуск UI/команд без rollback.
  Ошибки памяти/создания основных задач остаются фатальными. Выключенная сеть
  не включает C6; включение после старта и повторная настройка проверяются отдельно.
- OTA: неправильная плата, чип, протокол, версия/откат, повреждённые заголовок,
  SHA и образ; дробление первого заголовка между командами; размер/порядок,
  повтор последнего блока, обрыв и таймаут, взаимное исключение с записью,
  ошибка flash/verify/выбора раздела. Перезагрузка разрешается после отправки
  ответа. Проверяется создание исходной валидной загрузочной записи и rollback.
- ПК: восемь наборов ctest, включая существующую обработку опытов, loopback TCP,
  идентификацию платформы, OTA, factory manifest и offscreen UI.
  Отдельный DLL-мост соединяет PC-клиент с производственным C-парсером сервиса,
  а не только с другим симулятором протокола.
- ROM: SLIP, SYNC, security info/eFuse revision до любой записи, ошибки и
  повторы блоков, отмена/разрыв, MD5 каждой части. Полный порядок записи:
  приложение, загрузчик, таблица, otadata последней; NVS не стирается.
  На четырёх исходных файлах каждого настоящего пакета проверяются успешная
  установка на свою ревизию и отказ без стирания на противоположную.

## Два настоящих профиля

Финальные приложения после исправления ошибок старта:

| Профиль | Байт | SHA256 |
|---|---:|---|
| rev 100–199 | 1258720 | `2ef63ffb0e718153fbea52517b21359fcfdea99e95fe0f78abe2a938dfa08dd8` |
| rev 300–399 | 1260064 | `df0c9e04a111f22376b1ea8294c133880ebf373b018cee3f675fefab1dc686bb` |

После этих сборок повторены 16 запусков artifact-тестов (два профиля × две
архитектуры × image/manifest/ROM100/ROM300), все успешны. Также production C
bridge — 77/77; основной C-набор — 234844 assert, startup — 86 проверок.
ПК x64/x86 — 8/8 ctest (2298 проверок в каждой архитектуре).

`build/package` содержит образ IDF для ревизий 100–199;
`build-rev3/package` — независимо скомпилированный профиль 300–399.
Диапазоны взяты из заголовков готовых образов. Заголовки вручную не расширяются.
В каждом пакете четыре файла, JSON с адресами/хешами и `SHA256SUMS.txt`.
Адреса: bootloader 0x2000, table 0x8000, otadata 0xf000, приложение 0x20000.
OTA-разделы по 6 MiB, flash 16 MiB. `krenomer-esp32.bin` — приложение,
а не объединённый образ всего flash.

Для первоначальной установки нативный ROM-движок проверяет диапазоны настоящих
образов; успешные виртуальные цели — 100 и 300. Rev 301/302 безопасно отвергаются:
последовательность питания flash для них не реализована. Это не универсальная
прошивка P4. OTA использует проверку
диапазона IDF, но её физическая работа на этих ревизиях ещё не подтверждена.

## Что не подтверждено аппаратно

Ревизия экземпляра не прочитана, физические порты не открывались. Автовыбор
штатной панели реализуется BSP (ILI9881C/GT911, ST7123, ST7121), но не испытан.
Нужны проверки RS485 и реального темпа, питания USB-A, FAT32-носителей и SD
одновременно, C6/версии ESP-Hosted и радиоканала, RTC/INA, USB-C при USB-A,
первоначальной установки, переключения OTA/rollback и реального обрыва питания.
Подмена flash в тесте подтверждает логику, а не физическую атомарность памяти.

Без аккумулятора работа от внешнего питания считается нормальной. Порог 10 В
и процент 3S из STM32 не применяются. Батарея не обязательна для обновления.
CPU/rate пока неизвестны (`null`), а не выдаются за аппаратно измеренные числа.
Таймаут Modbus пока фиксирован; расширенная диагностика и смена адреса STM32
не перенесены полностью. Заводское состояние ESP-Hosted на C6 не изменяется.

Win7: выполнена проверка импортов x64/x86 при сборке; сам Windows 7 не
запускался. Для USB Serial/JTAG на Win7 может потребоваться драйвер. В exe
нет зависимости от Python/esptool; установка драйвера остаётся отдельной задачей.
