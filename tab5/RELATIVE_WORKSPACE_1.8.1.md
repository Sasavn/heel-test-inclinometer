# Tab5 1.8.1: рабочее пространство выравнивания

Локальный кандидат на базе 1.8.0, native RGB565 1280×720, без LVGL. Не устанавливался на прибор. Аппаратная пауза сохраняется. Один прежний измерительный сервис и общая RS485 с адресами 2/3; второго UART, четырёх головок, нового PC UI нет.

В Креномере сохраняются Углы / Качка / График / Запись. В Выравнивании эти слоты имеют собственную семантику: Выравнивание / Наблюдение / Качество пары / Журнал. Профиль и плоскостность явно недоступны: нужны отдельные маршрут, база и методика.

Наблюдение получает decoded Object−Reference до sensor-zero, затем вычитает отдельный REL-offset. История хранит максимум 128 записей, включая разрывы; время точки — max двух времён приёма. Новая точка требует увеличения ОБОИХ good-sequence. Redraw, изменение только одного ответа и повтор ключа не являются новой парой. UI опрашивает состояние примерно каждые 10мс; это наблюдаемые пары последнего состояния, не lossless поток всех UART-ответов и не частота физической выборки BWM427. Ось графика — реальные времена приёма, паузы не сжимаются до равного интервала. Между gap и числами линии нет, отсутствующие значения не заменяются нулём.

При плохом качестве вставляется один разрыв на наблюдаемую потерю пригодности; для восстановления истории нужны новые ответы обеих головок. Скачок времени точки более 500мс тоже разрывает серию. Повторное/обратное время не добавляет числовую точку. Rollback монотонного времени очищает представление и ждёт обе новые последовательности. Счётчики good в текущем measurement core монотонны до перезапуска программы; их неожиданный откат без новой generation не принимается за новый sample. Min/Max считаются с явного сброса/границы generation, не только по оставшимся 128 записям. Непригодный выброс в них не входит.

HOLD фиксирует значения, историю и Min/Max вместе с временем фиксации; отдельно указано время исходной точки. Измерения продолжаются. Статус/возраст/качество живой пары и проверка допуска остаются текущими: потеря опоры не оставляет зелёного пригодного результата. Выход из HOLD при потере данных показывает прочерк до пригодной новой пары. Смена режима, ролей, REL capture/reset сбрасывает старое наблюдение и HOLD.

Фильтр Наблюдения — опциональный presentation EMA с alpha=0.2 на уникальную пару, пять пар прогрева. После разрыва он начинает заново. Он не меняет исходные углы, REL CSV, старый фильтр Креномера или проверку допуска. Min/Max относятся к показанной серии, включая EMA, если включён. Это сглаживание с дополнительной задержкой, не улучшение паспортной точности. Значения Наблюдения и допуски явно заданы в градусах; основной экран сохраняет свой переключатель градусов/мм/м.

Пользовательский допуск задаётся отдельно по X/Y в диапазоне 0.01…90°, по умолчанию выключен, значение 0.10° на ось. Включённый допуск проверяется по текущему НЕФИЛЬТРОВАННОМУ относительному результату до округления, условие |Δ|≤limit для каждой оси. При непригодной паре оценка недоступна, включая HOLD. Допуск оператора не является погрешностью/accuracy BWM427 ±90° XY. Versioned NVS blob `tab5/workspace` хранит только допуски/выбор фильтра; HOLD/история/REL/запись не восстанавливаются после reboot. Ошибка NVS не меняет действующие настройки.

Качество пары показывает доступные RX ages/skew, good/errors, последний enum ошибки и streak. Время внутри датчика, аппаратная синхронность и раздельная гистограмма CRC/timeout недоступны. Пределы пригодности остаются 500мс/50мс; это транспортная политика, не доказательство динамической точности.

Журнал показывает фактические REL rows/quality-event gaps, queued/dropped, ошибки, открытие и успешное закрытие отдельно для SD/USB. Метаданные последней попытки START (имя, роли, offset, generation) сохраняются независимо от последующей смены текущих ролей/REL. Кэшированные статусы сверяются по имени сеанса. Нажатие STOP означает запрос: сначала прекращается приём, потом drain/flush/fsync/close; успех не подменяется нажатием. На ошибки записи/закрытия UI не показывает «закрыт успешно».

Схемы D2/D3 и Protocol2/S/R сохранены. REL CSV расширен двумя полями в конце: Event и ObservedUs. SAMPLE — аудит реального raw callback, может повторять ключ пары и не равен уникальному sample графика. GAP/RECOVERY — отдельное наблюдение изменения quality, без raw D2/D3-строки. Watchdog существующего storage router просыпается через 100мс даже при полном молчании обеих головок; это не второй poll task. Повтор неизменного quality не создаёт строку. Изменения mask могут давать несколько GAP-событий в одном физическом отказе. ObservedUs — время наблюдения, оба RX timestamp остаются исходными. Сеанс остаётся открытым во время outage до явного STOP; recovery продолжает тот же сеанс, не выполняет новый автоматический START. При переполнении очереди потеря отражается counters; доставка событий не объявляется гарантированной.

Режим/роли/REL/наблюдение/допуски блокируются во время REC, закрытия, OTA и передачи файлов. Управление резервируется атомарно в services против нового recorder/OTA/file transfer; NVS I/O идёт вне service lock. STOP остаётся доступен при отказе пары. Ранее известная граница STOP сохраняется: drain гарантирован для уже принятых service media queues, не для каждого callback, ещё находящегося в промежуточной storage_samples. Это не lossless acquisition.

Программные доказательства: production-core состояния, exact main/NVS/router функции с injected boundaries, production writer на временных host-файлах, native PNG обеих тем и regression/performance сравнение с чистой 1.8.0. Доказательств реальных minimum/largest heap, stack high-water, P4/LCD/PSRAM frame time, GPIO/media/Wi-Fi/bus timing или метрологической точности нет. Четыре .bin/ELF/map/partition/config и хэши находятся в feedback/2026-11-04-relative-workspace; публикацию и установку выполняет владелец отдельно.

Независимый review первого frozen-кандидата выявил два interleaving. Исправлены: clock берётся после measurement snapshot перед мутацией истории; storage router захватывает ненулевой64-bit epoch сеанса вместе с route state, а submit проверяет его под тем же service lock, что и enqueue. STOP/drain/START B отвергает отложенную строку или quality-event A. Epoch внутренний, не изменяет CSV/PC wire schema. Проверены ожидаемые fail на неизменённой QA-копии первого кандидата и pass на исправленном production-коде (qa-fixes-fail-pass.json). Исходные результаты QA не переписаны.
