# Крупный native-интерфейс Tab5, 1.7.0

Образец: `tab5-feedback/2026-10-23-ui-large/mockup.html`, `proto.html`,
`ENCODER.md`, каталоги `png` и `png-encoder`. Размер кадра — 1280×720.
Это перенос согласованной крупной компоновки в существующий RGB565-рендерер;
LVGL runtime не подключается.

## Экран

Шесть страниц: **Углы, Качка, График, Запись, Настройки, Сеть**.
Левая панель шириной 152 px содержит шесть пунктов по 120 px. Общая строка
состояния высотой 56 px показывает часы, запись, CPU, внутреннюю память,
PSRAM и питание; неизвестные значения остаются прочерками.

Два датчика занимают две горизонтальные карточки. Основные углы — Roboto
Bold 108 px; для значений, не помещающихся в 380 px, применяется числовой
64 px, чтобы знак и градусы не обрезались. Названия страниц — 48 px,
основные кнопки — 36 px, подписи — 24–28 px. Светлая и тёмная темы используют
палитру согласованного образца. Качка вынесена в отдельную страницу.

График сохраняет существующие историю, разрывы при отсутствии данных,
масштабирование и оптимизированный RGB565-буфер. Измерения, EMA, ноль,
CSV и запись на носители не пересчитываются интерфейсом.

Настройки и сеть имеют прокручиваемую область: нижние строки доступны
касанием и энкодером. Яркость — 10–100 %, шаг 10 %, сохранение через
существующий NVS и штатный BSP дисплея. Значение 0 в старом API действия
означает «не менять яркость».

## Ввод без сенсора

Аппаратный драйвер отделён от интерфейса. Очередь принимает относительный
поворот, короткое нажатие, долгое нажатие и координаты касания; обрабатывает
их одна UI-задача под существующим mutex. GPIO и адрес I2C не назначены:
модель аппаратного энкодера ещё не выбрана.

- **Меню:** поворот меняет страницу; нажатие входит в список её действий.
- **Выбор:** поворот перемещает фокус; нажатие запускает то же действие,
  что касание. Долгое нажатие возвращает к меню.
- **Правка:** поворот меняет число с ограничениями диапазона, нажатие
  принимает, долгое нажатие возвращает исходное значение. Шестой и
  последующие щелчки с промежутком менее 90 мс используют шаг ×5.
- **Окно:** фокус не покидает окно; у подтверждения исходный выбор — отмена.
  Долгое нажатие закрывает окно с отменой.

После касания или 15 с без энкодера рамка скрывается. Первое событие
энкодера только будит рамку. За концами списков нет перехода по кругу.
На странице качки нет действий: нажатие сообщает об этом.

## Дата и время

«Настройки → Дата и время → Изменить» открывает ручной ввод и команду
**«По WiFi»**. Поля доступны касанием и энкодером. Ручной ввод проверяет
настоящую календарную дату, високосный год и диапазон RTC 2000–2099.
Отмена ручной правки не посылает действие установки часов.

Часовой пояс задаётся как смещение UTC, от −12:00 до +14:00, шаг 15 минут;
UTC+00:00 — допустимое отдельное значение. Штатный дефолт — UTC+03:00.
Во flash хранится только пояс, а не «продолжающая идти» копия времени.
Системные часы используют UTC, RTC — местное время для совместимости с
прежними записями прибора. Преобразование выполняется один раз, без
глобального `TZ`, `mktime` и повторного добавления трёх часов.

Сетевая синхронизация запускается только явным действием. Без STA она
отклоняется: одной точки доступа AP недостаточно для интернета. Выделенная
задача получает NTP с общим бюджетом 8 с, включая DNS/UDP; UI-поток не ждёт
сеть. Полученный UTC применяется основным потоком к системным часам и RTC.
Отдельно сообщаются ошибка сети, ошибка записи RTC и ошибка сохранения
пояса. «По WiFi» — самостоятельное действие установки: закрытие окна после
отправки запроса не отменяет уже отправленный запрос синхронизации.

Коррекция календарных часов не перезапускает запись. `Ms` и длительность
остаются на монотонном таймере; календарные `Date`/`Time` могут измениться
скачком. Для сравнения отсчётов после коррекции нужно использовать `Ms`.

Офлайн используется существующее действие **синхронизации времени с ПК**
в приложении регистратора. Оно работает по USB или локальному TCP без
NTP и интернета; автоматическая установка при подключении не добавляется.
Протокол сохраняет команду `set time`; поддержка пояса согласуется через
возможности прибора, старый STM32 не получает неизвестные аргументы.

## Эмулятор и проверка

`python tab5/tools/native_large_emulator.py --out .tools/native-large/captures`
собирает production native renderer и очередь GCC, создаёт кадры RGB565
без окна, браузера и платы. Кадры включают обе темы и состояния энкодера.

Для своего сценария используется `--scenario events.txt`: `RESET light`,
`ROT 1`, `PRESS`, `LONG`, `HOLD 600`, `WAIT 15000`, `TAP x y`,
`CAPTURE name`. `HOLD` моделирует порог долгого нажатия 600 мс без
повторного короткого нажатия при отпускании. Это программный эмулятор
контракта событий, а не проверка физической кнопки.

Сборка ESP-IDF выполняется без устройства. Измерение скорости host-рендера
не является измерением CPU, touch-to-display latency или FPS физического
Tab5. Проверки на самой плате остаются на паузе.
