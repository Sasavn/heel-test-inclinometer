# Tab5 1.6.3: ускорение интерфейса, 22.10.2026

## Результат на реальной плате

P4 revision103 / ST7121, USB COM11 через mesh-replica. Сначала записана
инструментированная 1.6.2 с прежним UI-объектом и прежними настройками дисплея;
затем окончательная 1.6.3. В обоих случаях главная страница, тёмная тема,
датчики отсутствуют, SD возвращает timeout263. Измерения каждого прогона около21с.

| Измеренный интервал | До | После |
|---|---:|---:|
| Средний REFR_START → REFR_READY | 116.17 мс | 15.34 мс |
| Средний tab5_ui_update | 18.12 мс | 2.73 мс |
| Количество render-циклов | 144 | 196 |
| Количество flush-вызовов | 4486 | 413 |
| Максимальный refresh | 123.60 мс | 21.02 мс |

Средний измеренный refresh быстрее в 7.57 раза; подготовка UI — в 6.64.
Это wall time обработчиков LVGL, **не процент загрузки CPU и не задержка
«касание → физический пиксель»**. RENDER_START → RENDER_READY в LVGL9.3
включает промежуточные flush; flush_us измеряет callback и поворот, но не
полную развёртку панели. Эти интервалы нельзя складывать.
Предел обновления показаний сохранён:100мс, около10Гц; 60FPS не заявляются.
Ускорение получено совокупностью изменений, отдельный вклад PPA не изолировался.

## Исправления

- Назначение неизменной роли больше не снимает и не добавляет все стили;
  local-style значения сравниваются для точного selector, включая inactive states.
- Уровни перерисовываются при изменении X/Y, качки, валидности или темы.
  Скрытые страницы измерений/записи освежаются перед показом.
- График сохраняет поступающие отсчёты на каждом update, но повторные
  одинаковые массивы не передаёт LVGL. Диапазон, легенда и тема учтены.
  Persistent scratch4800байт не расходует малый стек LVGL task.
- CONFIG_COMPILER_OPTIMIZATION_PERF=y вместо debug/Og; assertions сохранены.
- CONFIG_LVGL_PORT_ENABLE_PPA=y:90° поворачиваются аппаратным PPA.
  DMA2D копирование DPI уже было включено и сохранено.
- Два draw-буфера720×128 вместо720×32, PSRAM; buff_dma=false сохранён.
  Вместе с rotation buffer примерно540КиБ вместо135КиБ.
  Адреса draw-буферов выровнены64байта, stride alignment оставлен1,
  поскольку закреплённый PPA wrapper ожидает плотные RGB565 строки.

Новые диагностические команды: `ui perf reset`, затем через20с `ui perf`.
Возвращаются интервалы и счётчики, флаг PPA и ESP reset_reason.
Ни одна команда не меняет настройки измерения или содержимое файлов.

## Проверки

- Реальные IDF5.5.2 builds100–199 и300–399. Аппаратно прошит только103.
  Объекты main/UI принудительно удалены перед final build: редактор сохранял mtime.
- ROM проверил4/4 части,1735648байта; NVS сохранена.
  Итоговая версия1.6.3, boot_confirmed=true, uptime167с, RTC/AP работают.
- Обе темы проходят полные перерисовки без наблюдаемого зависания;
  длительности отдельных полных refresh находятся в metrics итогового JSON.
- Native реальный LVGL:76 снимков побайтно совпали с исходными.
  За20 одинаковых обновлений dashboard:20flush/390400pixels →0/0;
  timestamp-only:460flush/3446480pixels →0/0. Обе темы.
- Неизменный и полностью пустой график:0flush; новые точки, диапазон,
  легенда и тема вызывают перерисовку. Проверены движение, roll-only,
  свежесть после навигации и32 reinit без роста реестра style properties.
- Services234850 + startup86, measurement, calendar20, package4,
  реальный BSP/mutation suite и28 actual-image OTA/ROM mock-прогонов прошли.
- Независимый read-only review не обнаружил must-fix.

STM32, PC production, измерения, CSV/сетевой протокол, RTC и сервисы носителей
не изменены. Физические касания/точность данных и запись на носители этим
прогоном не подтверждены. Оформление проверено native-pixel сравнением,
физическое изображение отдельно не фотографировалось. Это короткие аппаратные
прогоны, не испытание круглосуточной стабильности. Между промежуточными окнами
наблюдался один перезапуск; причина тогда не фиксировалась, повторный тест
обеих тем прошёл. В финальный образ добавлен reset_reason для диагностики.
