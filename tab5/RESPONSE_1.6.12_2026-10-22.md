# Tab5 1.6.12: разрывы и нагрузка UI, 22.10.2026

**Прошита 1.6.12-esp32 на P4 revision103/ST7121.** На проверках CPU 6–15%, максимальный кадр 41.9 мс, пропусков блокировки UI нет. Поздняя проверка: uptime 213.9–234.2 с; оба датчика отвечают без прироста ошибок. Сохранены 10 Гц / α=0,5 / gap15 мс.

## Что изменилось

- Новые данные для UI снимаются после блокировки экрана, время — после
  снимка. Новый отсчёт больше не отбрасывается как «из будущего» из-за
  времени начала старой итерации.
- Живые числа/уровень/график: последний decoded угол минус сохранённый ноль.
  Подпись «Угол без сглаживания» явная. Фильтр median3/EMA для записи и оценки
  качки сохранён. Интерполяция графика не дописывает CSV/USB/raw history.
- Во всех диапазонах соединяются реальные точки через ограниченную короткую
  паузу; offline/три ошибки подряд/невалидная ось/долгая пауза остаются разрывами.
  Хвост не экстраполируется. Y сплошные и отличаются оттенком.
- UART DIR34 переключается в TX_DONE ISR. RX читает уже принятый полный кадр
  перед проверкой 30-мс deadline; устаревшие байты очищаются только до TX.
  UART ISR в IRAM; UART и LVGL разнесены по ядрам.
- Главный аппаратный профиль нашёл дорогие круговые рамки: на промежуточной
  сборке border занял 6,02 с, fill 2,82 с за 19,49 с. Шкалы 200×200 и график
  1040×364 теперь RGB565-буферы в PSRAM. Шкала обновляется при изменении
  пикселя указателя, а не каждого шумового отсчёта. Нет полупрозрачной эллипсы.
  При нехватке памяти остаётся обычный LVGL fallback.
- График рисуется до 5 Гц, текущие числа до 10 Гц. Кнопки/касания сохранены.
- LVGL получает время из монотонного esp_timer_get_time через lv_tick_set_cb.
  Периодический tick порта остановлен: он больше не ждёт timer_mux touch I/O
  и не повышает приоритет taskLVGL до esp_timer. В ожидании DMA задача спит,
  а не крутит пустой цикл. Полноразмерные partial draw-буферы уменьшают дробление.
- Ошибочные SD mount повторяются с задержками 2/4/8/16/30 с от завершения,
  а не непрерывно каждые 2 с. Вставка карты без CD может обнаружиться до 30 с;
  `sd retry` запускает проверку сразу. USB attach не замедлен. Диагностические
  `sd auto off/on` не отменяют уже начатую операцию и не меняют запись.
- `ui perf` содержит возраст отсчёта/ожидание DMA/профиль draw primitives;
  `ui tasks` возвращает один JSON, чтобы не переполнять очередь USB из 4 строк.

## Проверка

98 native RGB565 сценариев, 0 ошибок геометрии. Проверены четыре линии,
цвета, gap/head/tail, pixel buffer, уровни, движение/субпиксельный шум и
неизменность входного snapshot. 46 515 graph assertions; UART late-wake,
gap/CRC/timeout, guards/clipping plot/level, backoff и API управления retry PASS.
Services: 234850 + startup86. Actual package OTA/ROM mocks x64/x86: 14 запусков.
Реальная плата: четыре части ROM-MD5, запуск/boot_confirmed, два временных
интервала с живыми датчиками, включая поздний после заполнения окна качки.

Увеличение PSRAM преднамеренное: два full RGB565 draw-буфера и PPA около
5,53 МБ, график 757120 Б и две шкалы 160000 Б; внутреннюю SRAM для них не используем.
Нельзя выдавать render/sample-age за физически замеренное время «поворот→пиксель»:
такого измерения не было. Host motion fixtures синтетические. В этой доработке
собран/прошит только профиль revision100–199; rev3 отдельно не проверялся.
